# Сайт NANAVA

Статика без сборки: три страницы. Кладётся на любой хостинг (Vercel, Netlify,
шаред) — просто залить папку `site/`.

## Запуск локально
```
cd site && python3 -m http.server 8787
```
→ http://localhost:8787

## Страницы (v2 — после созвона 21.08)
Фон везде #F1F1EF. Язык EN по умолчанию, переключатель EN/BY. Цены в евро.
- `index.html` — главная: баннеры на всю ширину (ushatava): hero
  «Shop by Look» (3 вещи слева, 3 справа), баннер Objects, карусель «New in»,
  категории. Постеры с моделями заменят hero, когда будут сгенерены.
- `catalog.html` — сайдбар слева (категории + дизайнер), справа фильтр
  по моделям, цвет и сортировка (ssense). Без свотчей и закладок.
  `?cat=bags` — категория, `?model=katya` — модель.
  Фильтр **MODEL** — выпадашка с лицами всего ростера (включая Булочку и тех,
  по кому кадров ещё нет): показывает вещи, снятые на этого человека. Данные —
  `data/faces.js` + `img/models/<имя>/face.webp`, собирает
  `python3 scripts/build_models.py`.
- `product.html?id=<id>` — верстка ssense: слева описание, в центре фото,
  справа покупка. Размер предвыбран, кнопка всегда активна.
- `bag.html` — корзина как ssense shopping bag (localStorage), checkout →
  модалка «пока не в продаже».
- `models.html` — **внутренняя** страница команды (noindex, из навигации
  не видна), две вкладки: «Люди» — раскадровки, рост/телосложение, вещи
  на каждой модели; «Вещи» — раскадровка каждой вещи, замена и добавление
  кадров, отметка эталонных кадров для генерации.
  Данные — `data/models.js`, собирается `python3 scripts/build_models.py`;
  редактирование (фото → новая раскадровка) — под локальным сервером
  `python3 scripts/models_server.py`.

## Админ-режим: правка картинок прямо на живом сайте
`assets/edit.js` подключён ко всем страницам, но обычный посетитель его не
видит: скрипт выходит первой же строкой, пока в браузере нет админского
флага. Включить у себя — один раз открыть

    https://nanava.store/?nnv-studio=1        (выключить: ?nnv-studio=0)

Дальше кнопка «Ключи» в шапке редактора: свой ключ Google (Gemini) и
fine-grained токен GitHub на репозиторий сайта с правом **Contents: read and
write**. Оба лежат только в localStorage этого браузера, уходят только на
`generativelanguage.googleapis.com` и `api.github.com`. Заводите отдельный
ключ Google с лимитом — он виден в этом браузере, как любой ключ на клиенте.

Работа: ховер по картинке → «Править» → обводим зоны (прямоугольник или
кисть), пишем, что поменять — ко всей правке или к конкретной зоне, туда же
кидаем картинки-референсы (перетаскиванием, ⌘V или кликом) → варианты →
шторка «было/стало» → «Применить». Применение коммитит новый webp прямо в
репозиторий, прод обновляется за минуту.

Как это работает внутри: координаты зоны уходят в Nano Banana дважды —
словами и вторым кадром с розовой обводкой; ответ модели вклеивается
**только внутрь зоны** с растушёвкой и подгонкой тона по пикселям вне
маски, поэтому вне зоны кадр остаётся прежним и не деградирует от повторных
правок. Мелкая зона (<30% кадра) правится режимом crop: вырезаем с запасом,
2K, вклеиваем обратно. Зона со своим текстом или картинкой = отдельный
проход. Смета видна до нажатия (~$0.10 за проход в 2K).

Откат — обычный `git revert` коммита правки.

Локально, не трогая прод:
```
python3 scripts/edit_server.py
```
Тот же сайт с той же кнопкой, но «Применить» пишет в файл на диске (копия
«до» и промпты — в `refs/edits/<путь>/`). Тот же алгоритм пакетно из
терминала — `scripts/edit_image.py`.

## Данные
- `data/items.js` — ЕДИНСТВЕННЫЙ файл, который правим: 18 вещей, у каждой
  `id, title, category (clothes|bags|accessories|objects), price, color`
  (свотч), `sku, lead` (короткая строка), `desc, image, images`.
- `img/p01.webp … p18.webp` — главные кадры.
- `process: [{src, cap}]` у вещи — листы «процесса работы» (тип 4 по
  PLAYBOOK): лист целиком под фото, блок DESIGN PROCESS. Файлы —
  `img/process/*.webp`, собираются из `refs/process/` командой
  `python3 scripts/add_process.py`; один лист может стоять у нескольких
  вещей. Лайн-ап сезона — полоса `#b-process` на главной.
- Когда появятся пролётки (до 6 кадров на вещь) — добавить пути в `images`,
  и расширить галерею в `app.js` (сейчас рендерится `image` + зум).
